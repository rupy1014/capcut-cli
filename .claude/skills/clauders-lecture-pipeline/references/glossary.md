# 클로더즈 자막 퇴고 가이드

강의 전사 자막을 다듬을 때의 판단 기준. 실행은 `scripts/proofmerge.py`가 하고, 이 문서는 **왜 그렇게 자르고 고치는지**를 적는다.

용어 소스: `~/sideProjects/openhow/examples/clauders.ai/docs` (약 14k줄 커리큘럼).
표기 컨벤션 정본: `docs/agent-rules/capcut-draft-editing-workflow.md` §4. `~/.claude/capcut-cli.md`는 과거 개인 경로이며 현재 규칙 선택 근거로 쓰지 않는다.

## 1. 사전 3층 — 무엇을 어디에 넣나

`assets/clauders-terms.json`

| 층 | 성격 | 새 항목을 넣는 기준 |
| --- | --- | --- |
| `confirmed` | 실제 작업에서 확인된 교정 | 승인된 표기를 우선하되, 이번 화면·발화와 대조한다. 새 근거와 충돌하면 원문 유지·확인 보고 |
| `candidates` | 커리큘럼 용어에서 추정한 오인식 | 아직 실물 전사에서 확인 못 한 것. 프리뷰에서 틀리면 즉시 뺀다. |
| `notation` | 표기 정규화 | 오인식이 아니라 스타일. 약어 소문자, 조사 붙이기 등. |

`<작업폴더>/overrides.json` — 이번 전사에만 있는 것. 회차가 바뀌면 버린다.

| 키 | 용도 | 주의 |
| --- | --- | --- |
| `EMPTY` | 텍스트 슬롯 비우기 | 오디오는 안 건드린다. 병합 흡수·자막 중복에만 사용하고 실패 발화·군말은 실제 source cut과 대조 |
| `OVERRIDE` | 뜻을 보존한 오인식·표기 교정 | 원본 인덱스 기준. `texts-after-silence.json`의 `original_index`. 뜻을 바꾸는 재작성 금지 |

적용 순서는 `confirmed → candidates → notation`이고, 앞 규칙의 결과에 뒤 규칙이 다시 걸린다. **긴 패턴을 먼저 둔다** — `클로드 → Claude`가 위에 있으면 `클로드 엠디`가 `Claude 엠디`가 돼서 `CLAUDE.md` 규칙이 영영 안 걸린다.

병합 후에도 사전을 한 번 더 적용한다. cue 경계로 쪼개진 용어(`빌린` + `키` → `빌링키`)는 합친 다음에야 잡힌다.

## 2. 커리큘럼 블록별 용어 지도

자동 자막이 어떤 블록에서 무엇을 틀리는지 미리 알면 프리뷰를 훨씬 빨리 읽는다.

| 커리큘럼 블록 | 자주 나오는 용어 | 흔한 오인식 |
| --- | --- | --- |
| **시작하기** (`getting-started/`) 설치·VS Code·CLI·신규 프로젝트 | Claude Code, VS Code, 터미널, 폴더, cli, git init, "해줘" | `클라우드 코드`→Claude Code, `브이에스 코드`→VS Code, `씨엘아이`→cli |
| **초보 개념잡기** (`claude-code-intro/`) 모델 선택·방향·좋은 프롬프트 | Opus, Sonnet, Haiku, CLAUDE.md, `docs/`, 프롬프트, context | `클로드 엠디`→CLAUDE.md, `오퍼스`→Opus, `소네트`→Sonnet, `컨텍스트`→context |
| **자동화 입문** (`automation/`) 4장치 + `/write 1화` | commands, agent, sub-agent, skill, hooks, workflow, dsclaude, `drafts/`, proofreader | `커맨드`→commands, `훅`→hooks, `서브 에이전트`→sub-agent, `워크플로우`→workflow |
| **서비스 만들기** (`build-service/`) 아이디어→PRD→배포→PMF→결제 | 린스타트업, prd, mvp, mlp, pmf, Vercel, GitHub, 배포, 디버깅, 피드백, 모객, 부트페이, PG사 | `린스타터업`→린스타트업, `피알디`→prd, `버셀`→Vercel, `베포`→배포, `파업화`→사업화, `피디백`→피드백 |

새 용어의 커리큘럼 표기는 후보 근거다. 고유명사·파일명은 화면녹화 프레임으로 확인한다(`goal.md`·`getdesign.md`·`Mobbin` 등). 확신 없으면 원문을 유지하고 목록으로 보고한다. 즉흥 강의의 대본은 용어·표기 근거로만 쓰고 대본 구조대로 내용을 자르지 않는다.

## 3. 표기 컨벤션

**약어는 소문자**: `ai api llm mcp cli ide seo css html mvp mlp prd pmf cta ppt`
**대문자 유지**: `DB UX DevOps JavaScript PG사`, 단일 알파벳 `A B`
**고유명사 원표기**: `Claude` `Claude Code` `VS Code` `GitHub` `Git` `Vercel` `Notion` `Slack` `Next.js` `Cursor` `ChatGPT` `Codex` `Anthropic` `Opus` `Sonnet` `Haiku` `CLAUDE.md` `AGENTS.md`
**기능어는 영어 소문자**: `agent sub-agent commands hooks skill workflow context working`
**한글 유지**: `메뉴얼`(매뉴얼 아님) `컨텐츠` `메모리` `터미널` `폴더` `리서치` `레퍼런스` `프롬프트` `커밋` `배포` `디버깅`

> **커리큘럼 문서와 일부러 다른 부분**: docs는 `MVP` `PRD` `PMF` `CTA`를 대문자로 쓴다. 자막에서는 "약어 소문자" 컨벤션을 따라 소문자로 간다. 이 판단을 뒤집고 싶으면 `assets/clauders-terms.json`의 `notation` 층에서 해당 줄만 지우면 된다 — 다른 층은 건드릴 필요 없다.

**보존**: `이`(지시관형사 — `이 회차`), `이런`(지시어), `그 회차`. 화면 UI를 가리키는 "메뉴"는 안 바꾼다.

**조사 붙이기**: 용어를 영문으로 치환하면 뒤따르던 조사가 홀로 떨어진다(`피알디 를` → `prd 를`). `을 를 의 로 으로 에 에서 에게 부터 까지 처럼 보다`는 앞말에 붙인다. `이 가 은 는 도 만 와 과`는 지시어·감탄사·용언과 헷갈려 제외한다.

## 4. 군말 제거

독립 토큰 `어 음 아 응` 등은 군말 **후보**다. 기존 사전의 `네 그 뭐 자 예`·접속사·지시부사(`그리고 그래서 그런데 근데 그러면 그러니까 그리고는 이렇게`)도 일괄 삭제하지 않고 문맥을 읽는다. 응답·인용·논리 연결·지시 의미가 있으면 보존한다.

군말로 확정하면 **오디오에서도 삭제**한다. `proofmerge.py`의 token 제거만 적용하면 FAIL이다. 앞뒤 어절 사이 음성대역 최소점으로 경계를 잡고, 적용 전 미리보기를 재전사해 모든 join 앞뒤 문장을 읽는다. 어절 일부 컷은 `silence-edit.py --removals`의 clip 전체 삭제로 대체하지 않는다.

**단어 일부는 건드리지 않는다**: `어떤` `없어` `그다음에` `예를 들면` `그리고요` `그래서인지` `이렇게요`. 토큰 정확 일치로만 제거한다.

`이`·`이런`은 제거 목록에 **없다**. `이렇게`도 실제 지시 의미가 있으면 보존한다. token 일치만으로 의미 삭제를 승인하지 않는다.

## 5. 병합과 줄바꿈

STT 자막은 1~2초 조각으로 과분할돼 있다. **병합만 하면 CapCut 조각 경계가 남는다.** 일반 CapCut 퇴고는 어절 시각 기반 DP로 cue 경계를 다시 잡은 뒤 전량 정독해 끊기/붙이기를 확정한다. 절차는 `../../capcut-silence-editing/references/manual-semantic-caption-reflow.md`.

**cue 규격**: 한 줄 15자(**공백 포함**, 영문·숫자만 0.55), 최대 2줄. 3줄 금지, cue 0.5–7초. 긴 단일 어절은 예외로 두고 쪼개지 않는다.

옛 병합 규칙(2026-08-04: 문장 종결·gap 0.7초·30자·7초·2×15자)은 초안 도구의 기준이었다. 현재 최종 경계는 **어절 시각 기반 재분할**로 대체한다. 문장끝 < 연결어미 < 조사 < 명사연쇄 < 관형형 < 지시어 순으로 선호하고 의존명사·보조용언 앞은 금지한다. 연결어미 판정에 단독 `지`·`게`는 금지한다(`이미지`·`쉽게` 오탐).

원본 `words` 시각을 컷에 투영해 어절에 붙인다. 재분할 후 시작 0.3초 안에 소리 없는 cue는 1.2초 안 발화 onset으로 옮기고 끝은 유지한다. onset 불명확은 유지·보고한다.

**줄바꿈은 어절이 아니라 어구(phrase) 단위다.** 아래는 점수가 아니라 **하드필터** — 점수로 두면 길이 균형에 밀린다.

1. 의존명사를 줄머리로 보내지 않는다 — `작동시킬 / 수 있거든요` ✗
2. 의존명사 뒤 보조용언을 떼지 않는다 — `할 수 / 있습니다` ✗
3. 관형형 + 명사를 끊지 않는다 — `정할 / 수` ✗
4. 수 + 단위를 끊지 않는다 — `두 / 군데` ✗
5. 지시관형사 + 명사를 끊지 않는다 — `이 / 회차` ✗
6. 영문 인접을 끊지 않는다

의존명사는 조사까지 포함해 정확히 매칭한다(`수·것·거·때·데·줄·뿐·등·중·후·전·점·텐데·테니·터`). `startswith`로 하면 `중간에`를 `중`으로, `데모`를 `데`로 오인한다.

기존 줄바꿈 초안 점수는 접속사 앞 `+4`, 연결/종결어미 뒤 `+3`, 한쪽 줄 4자 미만 `-8`, 길이 균형 `-|Δ|×0.6`이었다. 현재도 초안 참고로만 쓰며 cue DP·전량 정독의 최종 판단을 대신하지 않는다.

**자연스러운 분절이 없으면 어절을 억지로 쪼개지 않는다.** 0803의 평균 12자·20자 이상 허용은 사용자 수정 SRT의 보존형 사례다. 일반 CapCut 자막은 위 15자 표시폭 규격으로 의미 단위를 다시 나누고 전량 정독한다.

어구가 하나로 묶여 나눌 자리가 없으면 단일 어절 예외 여부를 확인한다(`application/json으로`). 2×15자를 못 맞추는 여러 어절은 인접 cue까지 경계를 다시 잡는다. 길이 균형만으로 의미 보존을 단정하지 않는다.

> **단순 글자 수와 표시폭을 구분한다.** `commands 랑 hooks을`은 글자 수 17자여도 영문 0.55로 따로 센다. `caption-metrics.json`의 `lines_over_15`는 단순 길이 참고값이며 새 표시폭 검사를 대신하지 않는다. 분량을 맞추려고 `OVERRIDE`로 발화 뜻을 바꾸지 않는다.

## 6. 작업 순서

```bash
scripts/proofmerge.py --work <작업폴더>            # 프리뷰
# proofread-preview.txt 를 before→after 전체 정독
scripts/proofmerge.py --work <작업폴더> --apply
```

프리뷰는 cue마다 `raw:` 줄에 원본을 같이 보여준다. **정독 없이 `--apply` 하지 않는다.** `candidates`는 추정이며 `confirmed`도 이번 화면·발화와 대조한다. `지향하지 않는`→`지양하지 않는`처럼 뜻이 반대가 되는 교정은 금지한다. DP 재분할 뒤 최종본도 전량 읽고 의도한 교정 외 어절 흐름 차이가 0인지 검증한다.

추정 교정이 의심스러우면 한 번 꺼서 비교한다.

```bash
scripts/proofmerge.py --work <작업폴더> --no-candidates
```

`caption-metrics.json`의 `rule_hits`에 어떤 규칙이 몇 번 걸렸는지 나온다. 한 번도 안 걸린 규칙은 이번 회차에서 무의미했다는 뜻이고, 과하게 걸린 규칙은 오탐 의심 대상이다.

## 7. 새 교정을 확정할 때

1. 프리뷰에서 오인식을 발견한다.
2. 커리큘럼 문서를 참고하고 (`rg '<용어>' ~/sideProjects/openhow/examples/clauders.ai/docs`), 고유명사·파일명은 화면녹화 프레임과 실제 발화로 확인한다.
3. 회차를 넘어 반복될 것 같으면 `assets/clauders-terms.json`의 `confirmed`에, 이번 전사 한정이면 `overrides.json`의 `OVERRIDE`에 넣는다.
4. 확신이 낮으면 **원문 유지 + 후보 목록 보고**한다. 사용자 판단이 필요한 항목은 모아서 한 번에 전달한다.

## 8. 하지 말 것

- “적극적 편집”을 임계 강화나 대본 구조 컷으로 해석하기 — 무음·재발화 작업은 요청 범위와 상위 안전 게이트를 따른다.
- 반복 발화·군말의 자막만 지우고 오디오를 남기기 — FAIL이다. 실제 source cut을 적용하고 전체 clip 삭제가 맞을 때만 `silence-edit.py --removals`를 쓴다.
- `EMPTY`만으로 오디오 컷을 결정하기 — 병합 흡수·자막 중복이면 소리를 보존한다. 실패 발화·군말이면 별도 source cut으로 오디오도 지운다.
- 자동 생성 기본 스타일(font size 15, 배경 없음) 그대로 완료 보고하기 — donor 스타일을 대조하고 흰 슬라이드면 검은 반투명 박스(alpha 0.6, `check_flag |= 16`)를 확인한다.
- 줄바꿈만 바꾸면 되는 상황에서 텍스트·타이밍까지 다시 쓰기 — `\n` 위치만 옮기는 게 가장 안전하다.
