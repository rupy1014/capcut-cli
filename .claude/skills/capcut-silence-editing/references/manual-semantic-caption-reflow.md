# 수동 의미단위 자막 재배치

## 적용 모드 선택

다음 두 모드 중 하나를 먼저 고른다. 일반 CapCut 퇴고는 어절 시각 기반 DP로 초안을 만들고 **전량 정독 후** 수동 확정한다. 사용자 수정 SRT의 cue·타임코드 보존형 재배치는 자동 점수로 최종 의미 경계를 결정하지 않는다.

1. **일반 CapCut 자막 퇴고**
   - `docs/agent-rules/capcut-draft-editing-workflow.md`의 자막 규칙을 그대로 적용한다.
   - cue 병합만으로는 CapCut 조각 경계가 남는다. 원본 `words`의 source 시각을 컷에 투영하고 퇴고본 어절에 정합해 cue 경계를 DP로 다시 잡는다(미정합은 cue 안 보간 후 확인).
   - 경계 선호는 문장끝 < 연결어미 < 조사 < 명사연쇄 < 관형형 < 지시어다. 의존명사·보조용언 앞은 금지한다. 연결어미 판정에 단독 `지`·`게`를 넣지 않는다(`이미지`·`쉽게` 오탐). 상세 비용은 draft 워크플로 §4.
   - 결과를 처음부터 끝까지 읽고 끊기/붙이기와 줄 위치를 지정한다. 자동 DP 통과만으로 완료하지 않는다.
   - 기본 제한은 한 줄 15자(**공백 포함**, 영문·숫자만 0.55), 최대 2줄, cue 0.5–7초다.
2. **사용자 수정 SRT의 수동 재배치**
   - 사용자가 직접 고친 구간이나 분절 습관을 기준선으로 삼는다.
   - 사용자가 sync보다 의미를 우선하거나 cue 번호·타임코드 보존을 요청하면, cue 수와 타임코드는 유지한 채 텍스트를 인접 cue 사이에서 옮긴다.
   - 사용자의 실제 패턴이 한 줄 15자를 넘으면 일반 제한보다 그 패턴을 우선하되 1–2줄은 유지한다.

두 모드를 섞지 않는다. 일반 CapCut 퇴고에서 cue 수 보존을 기본값으로 강제하지 않고, 사용자 SRT 모드에서 임의 병합으로 사용자가 고친 범위를 다시 쓰지 않는다.

## 기준선 보존

- 수정본과 draft에서 새로 export한 원본을 비교해 사용자가 고친 cue 범위를 확정한다.
- 사용자가 이미 수정한 범위는 byte-for-byte 보존한다.
- 별도 결과 파일에서 작업하고 사용자 원본 SRT를 덮어쓰지 않는다.
- 최종 의미 경계는 전량 정독해 확정한다. 일반 모드는 DP 초안·어절 시각 재구성을, 사용자 SRT 모드는 수동 재배치표 조립·타임코드 복사를 자동화할 수 있다. 두 모드 모두 token 보존을 검증한다.

## 수동 작업 순서

1. 현재 cue 앞뒤 3–5개를 연속으로 읽는다.
2. cue 끝이 조사·수식어·연결어로 끊기면 뒤 어절을 가져오거나 해당 조각을 다음 cue로 보낸다.
3. 다음 cue가 `거`, `게`, `수`, `것`, `때문에`, `라고`, `하는`, `되는`처럼 의존적인 말로 시작하면 앞 cue와 다시 나눈다.
4. 긴 문장은 주제/조건, 설명/결과, 원인/결론, 병렬 항목 같은 절 경계에서 나눈다.
5. 자연스러운 분절이 없으면 글자 수를 맞추려고 억지로 두 줄을 만들지 말고 한 줄로 둔다.
6. 짧은 파편은 앞뒤 cue에 보내고, 필요한 경우 뒤 의미 단위를 순서대로 당겨 빈 슬롯을 채운다.
7. 즉흥 강의의 대본은 용어·표기 근거로만 쓴다. 대본 구조대로 내용을 자르거나 문장을 새로 쓰지 않는다.
8. 맞춤법·STT 교정과 군말 제거는 별도 패스로 수행한다. 고유명사·파일명은 화면녹화 프레임으로 확인하고 뜻을 바꾸지 않는다(`지향하지 않는`→`지양하지 않는` 금지). 불확실하면 원문 유지 후 목록 보고한다. 재배치만 요청했으면 token을 바꾸지 않는다. 군말을 제거하는 작업에서는 오디오에서도 지운다.
9. 반복 문구가 실제 반복 발화인지 자동자막 중복인지 불확실하면 보존한다. 실제 실패 발화로 확인되면 자막만 지우지 말고 앞 실패 오디오 source interval도 함께 제거한다.

## 0803에서 확인한 사용자 패턴

당시 사용자 수정 SRT의 보존형 사례다. 일반 CapCut 퇴고의 현재 15자 표시폭·어절 시각 재분할 규칙으로 자동 승격하지 않는다.

- cue마다 1–2줄이고 글자 수 균형보다 의미 완결을 우선한다.
- 평균 한 줄은 약 12자지만 의미가 온전하면 20자 이상도 허용한다.
- `사업자도 내면서 / 어떤 PG 써야 되는지`처럼 주제와 질문을 분리한다.
- `수수료는 얼마인지, / 싸게 받을 수는 없는지`처럼 병렬 의미를 줄 단위로 나눈다.
- `받더라도 수수료가 높거나 / 보증보험을 더 들라고 하거나`처럼 연결 어미를 다음 핵심어와 함께 둔다.
- cue 경계가 잘못됐으면 인접 cue 사이에서 어절을 옮긴다. sync가 조금 어긋나도 `거 참고하시고` 같은 파편을 혼자 남기지 않는다.

## 검증

공통:

- 모든 cue가 1–2줄이고 비어 있지 않은지 확인한다.
- 조사·의존명사·연결어로 시작하거나 수식어로 끝나는 줄을 전수 검토한다.
- 작업 범위 전체를 이어 읽어 누락·의도하지 않은 중복·순서 변경이 없는지 확인한다.

사용자 수정 SRT 모드:

- 사용자 보존 범위가 byte-for-byte 동일한지 확인한다.
- 보존을 약속한 cue 번호·타임코드·cue 수가 원본과 같은지 확인한다.
- 재배치만 했다면 작업 범위의 whitespace-normalized token 흐름이 원본과 같은지 확인한다.

일반 CapCut 자막 퇴고 모드:

- cue 0.5–7초, 한 줄 15자(공백 포함, 영문·숫자만 0.55, 긴 단일 어절 제외), 최대 2줄, text overlap 0을 확인한다.
- 의도한 교정 외 어절 흐름·순서·누락·중복 차이가 0인지 검증한다.
- 재분할 후 시작 0.3초 안에 소리가 없는 cue는 1.2초 안 첫 발화 onset으로 옮기고 끝은 유지한다. onset이 불명확하면 원문 시각을 유지해 보고한다.
- 시각은 어절 시각과 실제 발화에 근거하고 모든 cue·줄 경계를 전량 정독한다.
