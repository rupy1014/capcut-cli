# CapCut CLI 작업 규칙 (capcut-cli)

CapCut draft(자막·세그먼트)를 `capcut-cli`로 편집할 때 참조하는 규칙. 현재 실행 규칙은 [draft workflow](capcut-draft-editing-workflow.md)를 우선한다(§2.7 싱크·배치, §3.3 사전 레벨 측정·교집합, §4 어절 재분할, §5 검은 박스, §8 보고). 자막 퇴고·표기 통일 작업에서 이 파일을 rules로 읽는다.

## 도구 & 경로

- 일반 CLI 설치: `npm i -g capcut-cli` (bin: `capcut`, `capcut-cli`). 배포 패키지의 dist를 쓰는 일반 설치다. GitHub git URL 직접 설치는 피하고, 원형 마스크는 아래 로컬 빌드를 쓴다.
- 원형 마스크는 레포에서 빌드한 `dist/index.js`를 `node dist/index.js`로 실행한다. 전역 옛 설치본은 정사각 소재에 타원을 만든다(workflow §2.7).
- 프로젝트 경로: `~/Movies/CapCut/User Data/Projects/com.lveditor.draft/<프로젝트명>` (또는 `draft_info.json`이 있는 디렉터리). `<project>` 인자에 이 경로를 준다.
- 프로젝트 목록은 위 디렉터리를 `ls`로 확인 (전용 list 명령 없음).

## 작업 전 필수 (순서 지킴)

1. **CapCut 앱 완전 종료 확인** — `pgrep -x CapCut`. 실행 중이면 파일을 직접 고쳐도 앱이 메모리 상태로 덮어써 변경이 유실된다. 사용자에게 닫아달라고 요청하고 닫힌 뒤 적용한다. (강제 종료 금지 — 미저장 작업 보호)
   - **덮어쓰기 함정(중요)**: capcut-cli로 적용한 뒤에도, 그 전부터 열려 있던 CapCut 세션(도크·메뉴바에 잔존 포함)이 살아 있으면 나중에 자신의 옛 메모리 상태를 저장하며 내 변경을 **통째로 롤백**시킨다. `pgrep`이 순간 "닫힘"으로 나와도 안심하지 말 것. 적용 후 `draft_info.json` md5/mtime 변경만으로 덮임을 단정하거나 재적용하지 않는다. 앱은 열기만 해도 material 복제·자막 ±1프레임 스냅을 저장한다. 구조·텍스트 diff로 실제 롤백/사용자 편집인지 판정하고 닫힌 뒤 현재 상태를 기준선으로 삼는다.
   - 권장 순서: CapCut **완전 종료(⌘Q)** → capcut-cli로 일괄 적용·검증 → 앱 열기 확인은 사용자 요청·자동 재작성 진단 때만 선택 수행한다. capcut-cli 작업과 CapCut 편집을 **동시에 하지 않는다**. 확인용으로 연 CapCut에서 편집·저장하면 다시 덮일 수 있다.
2. **백업** — `cp draft_info.json draft_info.json.bak_<태그>_<timestamp>`. 작업마다 현재 상태로 새 백업(사용자가 그새 직접 편집했을 수 있음).
3. **현재 상태 재추출** — 매 작업 전 `capcut texts`로 다시 뽑는다. 사용자가 CapCut에서 직접 세그먼트를 지우거나 고칠 수 있으므로 인덱스가 아니라 **id 기준**으로 작업한다(id 기반이라 삭제된 세그먼트와 충돌 없음).

## 조사 / 편집 / 검증

- 조사: `capcut texts <proj>` → JSON 배열 `{id, start_us, duration_us, text}`. 그 외 `info` `tracks` `materials` `segments`.
- 개별 편집: `capcut set-text <proj> <id> <text>` (`-q`로 조용히). id는 앞 6~8자 prefix 매칭 가능.
- 일괄 편집: `capcut batch <proj>` ← stdin JSONL, 한 줄 = `{"cmd":"set-text","id":"<id>","text":"..."}`. 결과 `{"ok":true,"succeeded":N,"failed":0}`. cmd: set-text, shift, shift-all, speed, volume, opacity, trim.
- 병합으로 흡수된 빈 자막: `text` 를 `""` 로 set-text. (단독 세그먼트 삭제 명령은 없음. `capcut texts`가 빈 텍스트 자막은 내부 content 구조를 그대로 표시하는 특이점이 있으나 실제 저장값은 `"text":""`로 정상.)
- 검증: `capcut texts` 재추출 → 잔존 패턴 `jq + grep -c`로 0 확인. `jq empty draft_info.json`으로 유효 JSON 확인. 자막 총개수 비교.
- 대량 변환은 `jq` `gsub` 체인으로 batch JSONL을 생성하고 **적용 전 before→after 전체를 출력해 검토**한다. 긴 패턴/특수 케이스를 먼저(예: `서브에이전트`·`서브 에이전트` → `에이전트` 앞, `클로드 코드`·`클로드코드` → `클로드` 앞, `훅스` → `훅` 앞, `브이에스 코드` → `브이에스` 앞).

## 자막 퇴고 컨벤션 (이 사용자 기준)

STT 녹취 자막 교정 시 — **기본을 "문맥 정독" 강도로** 한다(이 사용자는 적극 교정 선호). 전체를 처음부터 끝까지 읽고, 한 자막만 보지 말고 **앞뒤 2~3줄을 연결해** 판단한다.

- **문맥 동음이의/의미 이상 교정(발화·화면 근거 필수)**: STT가 음만 맞고 뜻이 틀린 것을 문맥으로 잡는다. 한 자막만 보지 말고 앞뒤 2~3줄을 이어 읽어, 강의/창업/개발 문맥에서 의미가 어색한 단어를 찾는다. 예: "다 다를 수 있어"→"다 다룰 수 있어", "지켜야 되라고"→"된다고", "엔진이어링"→"엔지니어링", "포메시 있거든"→"포맷이 있거든", "강시하지"→"지시하지", "자동 하나"→"자동화", "어묵 메뉴얼"→"업무 메뉴얼", "1 년의"→"일련의", "안목지"→"암묵지", "만물려서"→"맞물려서", "도매인"→"도메인", "파업화"→"사업화", 문맥상 "뉴스"→"usecase".
- **군말/한 글자 응답어 제거**: 어/음/네/그/뭐/자/아/예/응 — 단, 단어 일부("어떤·없어·예를 들면")와 숫자 "네 가지(=4)", 의미 있는 연결은 보존하되 군말 접속사 판정은 workflow §4를 따른다. 독립 군말은 자막만 비우지 말고 오디오에서도 삭제한다(§3.3). 자막 중간·끝에 낀 독립 토큰(" 어 ", "예$", " 예 ")도 제거.
- **이음새 반복 정리 — 앞엣것 제거**: 같은 이음새(그래서/그리고/어/음 등)가 짧은 간격에 반복되면 **앞엣것**을 없앤다. ① 한 자막 안 연속 반복("그래서 그래서 ~"→"그래서 ~"). ② 인접 자막 겹침: 단독 `[그래서]` + `[그래서 ~]`, 또는 `[~ 그리고]` + `[그리고 ~]` → 앞 자막의 그것을 빈 문자열로. ③ 같은 말 더듬음(`[agents랑]` + `[agents랑]`, `[거의]` + `[거의]`)도 앞 실패 발화를 오디오 source interval에서 함께 삭제한다(workflow §3 5항). 단 "오케이 오케이" 같은 의도적 강조 반복은 보존. (탐지: 시간순 정렬 후 `[i].text` 끝과 `[i+1].text` 시작이 같은 이음새인지 jq로 스캔)
- **불확실하면 보류하고 사용자에게 묻는다**: 음을 어떤 단어로 복원할지 확신이 없는 잡음(예: "가찹기", "프리티인지", "코파일러신데 다드", "노력을 네모니까", "있어지를")은 추정으로 고치지 말고, "원래 뭐라고 한 건지" 한 번에 모아 사용자에게 확인한 뒤 교정한다.
- 고유명사·파일명은 화면녹화 프레임으로 확인한다(`goal.md`·`getdesign.md`·`Mobbin`). 뜻을 바꾸는 `지향하지 않는 → 지양하지 않는` 교정은 금지한다. 확신이 없으면 원문 유지 + 한 번에 사용자 확인 목록 보고. 즉흥 강의 대본은 용어·표기 근거로만 쓰고 구조 컷 근거로 쓰지 않는다.
- 화자 의미·말투는 보존. 다만 명백한 더듬음·동음이의 오류는 정리한다.
- 작업은 여러 차례 반복될 수 있다. 매 회차 `texts` 재추출 후 잔존 패턴이 다시 보이면(롤백/누락) 재적용한다.

## 표기 컨벤션 (사용자 선호 — 확정됨)

- **약어는 소문자**: `ai, seo, llm, mz, ppt, md, esc, html`
- **단일 알파벳은 대문자**: `A, B` (예: "비 회사"→"B 회사", "에이라고"→"A라고")
- **고유명사**: `VS Code`, `Claude`, `Claude Code`
- **기능어는 영어 소문자**: `agent, sub-agent, commands, hooks, hook, skill, workflow, context, working`
- **한글 유지**: `메뉴얼`(매뉴얼 아님 — 사용자가 직접 "메뉴얼"로 적음), 그리고 `컨텐츠 / 메모리 / 터미널 / 폴더 / 리서치 / 레퍼런스 / 템플릿 / 매니저 / 에디터 / 마크다운`. `에이전트`도 외래어지만 이 사용자는 `agent`로 영문화함(위 기능어 참조).
- **진짜 UI 메뉴는 안 바꿈**: "메뉴에서 New Terminal" 같은 화면 메뉴는 메뉴얼/영어로 치환하지 말 것.
- 범위가 모호할 때(어디까지 영어로/대소문자)는 한 번 물어 확정한다.

## 짧은 자막 병합 (0531 당시 전처리)

2026-10-22 현재 완료 기준은 workflow §4의 어절 시각 정합 → DP cue 재분할 → 전량 정독·끊기/붙이기 지정 → 어절 흐름 검증 → onset 보정이다. 아래 누적 병합만으로 완료하지 않는다. 한 줄은 공백 포함 15자(영문·숫자만 0.55), 최대 2줄이며, 옛 20자·2~3줄 규칙은 대체됐다.

"1초 이하 자막 없애줘"는 **빈 자막으로 비우는 게 아니라 인접 자막과 병합**(STT over-segmentation 정리)을 뜻한다. 병합 전처리 타이밍은 실제 그룹 첫 start ~ 마지막 end를 쓴다. 최종 cue 시각은 workflow §4의 어절 정합·onset 보정으로 정한다.

- **자막이 여러 텍스트 트랙에 분산**될 수 있다(0531은 메인 1111 + 보조 28). `capcut texts`는 두 트랙을 합쳐 시간순으로 반환하므로, 트랙 무관하게 **id 기준**으로 통합 병합한다. 트랙 식별은 draft의 `.tracks[]|select(.type=="text")`.
- **그룹핑 알고리즘**: ① forward 누적 — 1초 이하 자막을 누적하다가 (a)텍스트 있고 >1초, (b)누적 3.5초 초과, (c)다음이 접속사(`그리고/그래서/근데/자/또`)로 시작 → 그룹 마감. ② backward — 그래도 남은 1초 이하 자막은 직전 자막에 흡수(텍스트가 직전 끝과 중복이면 시간만 흡수). 0531 당시 목표는 1초 이하 0이었다. 현재 최종 기준은 0.5초 미만 0이며 의미 경계를 우선한다(workflow §4).
- **적용 방법**: capcut-cli엔 세그먼트 삭제가 없다. **텍스트는 `set-text`(content의 글자범위 스타일을 자동 처리)**, **시간 갱신·세그먼트 제거는 draft_info.json 직접 편집**(python으로 `.tracks[].segments`에서 제거 id 삭제 + 대표의 `target_timerange` 갱신, `json.dump(...,ensure_ascii=False)`). 순서: set-text 먼저 → draft 편집. 반드시 백업.
- **검증**: `capcut texts` 개수·최종 0.5초 미만 잔존 0, `capcut lint`로 overlap(겹침) 0 확인, `jq empty`. 대표만 남기고 흡수분을 모두 제거하므로 트랙 겹침은 발생하지 않아야 한다.
- **줄바꿈은 의미 단위로**(글자수 절반 X): 공백 포함 한 줄 15자·최대 2줄로 나누고 넘어가면 어절 시각 기반 cue 재분할을 한다(workflow §4). 경계 점수 — 끊기 좋은 곳: ① 접속사(그리고/그래서/근데/자/예를…) **앞** ② 종결어미(다/요/거든/같아/된다…) **뒤** ③ 연결어미(~고/~서/~며/~는데/~지만) **뒤**. 옛 감점 후보: 조사·관형형·1글자 어절 뒤, 의존명사·보조용언(않/수/것/거/때/데…) **앞**(예: "~지 않고", "~을 때", "~할 수"), 영어 복합어(Claude Code) 사이, 한 어절만 떨어지는 분할. 의존명사·보조용언 앞은 감점이 아니라 금지하고 단독 `지`·`게`를 연결어미로 판정하지 않는다(workflow §4). 길이 균형은 약하게만 반영. (규칙 기반이라 "라고/하는"처럼 형태소 경계가 모호한 일부는 어색할 수 있음 — 그런 자막은 개별 조정.)
