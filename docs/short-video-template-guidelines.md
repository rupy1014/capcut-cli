# Short Video Template Production Guidelines

이 문서는 캐릭터챗/웹툰 추천/애니메이션형 TikTok·YouTube Shorts 템플릿을 만들 때 반복 참조할 제작 가이드다. 현재 작업에서 나온 사용자 피드백을 기준으로 작성했다.

## 핵심 목표

- 단순히 이미지를 순서대로 보여주는 영상이 아니라, **리듬감 있는 숏폼 편집**이어야 한다.
- 애니메이션/웹툰 추천 영상처럼 **설명, 자막, 컷 전환, 감정 피크**가 맞물려야 한다.
- 웹툰 추천형 영상은 가능하면 **완성 이미지 한 장을 확대하는 방식**이 아니라, `배경 plate + 캐릭터 누끼 + 전경/날씨/빛 + 자막`으로 조립한 패널이어야 한다.
- 캐릭터 이미지는 화면을 채우되, **얼굴·시선·표정이 자막에 가리지 않아야 한다.**
- 웹툰형 영상에서 얼굴은 정보의 핵심이다. 의도한 극단 클로즈업이 아니라면 **머리, 눈, 입, 턱선이 프레임 밖으로 잘리면 실패**로 본다.
- 같은 이미지가 반복되더라도 카메라가 원점으로 리셋되면 안 된다. 자막만 바뀌는 구간은 모션이 이어져야 한다.

## 레이어형 웹툰 패널 구조

레퍼런스에 가까운 자연스러운 소개 영상은 단일 캐릭터 이미지를 크게 깔아서 만들기 어렵다. 기본 구조는 아래 순서다.

```text
1. background plate
   궁궐 / 방 / 숲 / 눈 / 위기 공간 등, 캐릭터 없는 9:16 배경

2. character cutout
   핵심 캐릭터만 정밀 누끼. 위치/크기/시선 방향을 샷마다 조절

3. contact integration
   바닥 그림자, 색온도 보정, rim light, 약한 fog로 배경에 붙인다

4. foreground overlay
   나뭇잎, 눈, 커튼, 안개, 창살, 빛줄기 등으로 깊이감을 만든다

5. caption / speech bubble
   얼굴 safe zone을 피해 얹는다
```

### 누끼 기준

- 모든 이미지를 억지로 누끼 딸 필요는 없다.
- 반복 등장하는 주인공/남주/핵심 조연 **6~8장만 정밀 누끼**로 둔다.
- 배경이 이미 완성된 이미지, 표지, 브릿지, 이벤트 UI, 단발 클로즈업은 누끼 없이 full panel로 써도 된다.
- 흰 배경 캐릭터는 edge-connected background 제거 방식이 좋다. 단순 white keying은 흰 옷/머리카락까지 날릴 수 있다.

### 배경 생성 기준

- 필요한 배경 plate는 `omj-imagegen`으로 별도 생성한다.
- prompt에는 반드시 `no characters, no text, no logos, no watermark`를 넣는다.
- 캐릭터를 얹을 빈 공간을 확보한다. 예: `empty center-lower area for character overlays`.
- 한 영상에는 최소 4~6개 배경 plate를 둔다. 같은 배경을 써도 시간대/색감/전경 overlay로 기능을 바꾼다.

### 합성 기준

- 캐릭터는 배경 위에 그냥 붙이지 말고 contact shadow를 넣는다.
- 배경과 캐릭터의 색온도가 다르면 약한 tint로 맞춘다.
- foreground overlay는 얼굴을 가리지 않는 가장자리/상단/하단에 둔다.
- 위기감은 빨간선보다 배경, 조명, 커튼, 안개, 짧은 컷으로 만든다.

## 실패 패턴

### 1. 같은 샷이 원점으로 반복됨

문제:
- 자막 큐마다 같은 이미지를 새 클립처럼 렌더링하면, 줌/팬이 매번 `p=0`에서 다시 시작한다.
- 결과적으로 같은 이미지가 “툭” 원점으로 돌아가며 반복돼 보인다.

금지:
- 같은 visual scene 안에서 자막 조각마다 카메라 모션을 리셋하지 않는다.
- `caption cue == visual cut`으로 취급하지 않는다.

원칙:
- `visual scene`과 `caption cue`를 분리한다.
- 카메라 모션은 visual scene 기준으로 계산한다.
- 자막은 visual scene 위에 얹는 오버레이로만 바꾼다.

구현 기준:
```text
bad:  p = (t - caption_start) / caption_duration
okay: p = (t - visual_scene_start) / visual_scene_duration
```

### 2. 리듬감 부족

문제:
- 1~2초마다 이미지가 바뀌어도, 같은 줌/같은 위치/같은 자막 배치면 지루하다.
- 컷 밀도만 높다고 리듬감이 생기지 않는다.

원칙:
- 4~6초마다 화면의 **기능**이 바뀌어야 한다.
- 같은 작품 설명 안에서도 감정 단계가 올라가야 한다.

권장 리듬 구조:
```text
훅 → 효능/취향 제시 → 작품명/표지 → 브릿지 → 주인공 과거 → 사건 발화 → 위기 피크 → 시간 점프/재회 → 질문 → 두 번째 맛보기 → 이벤트/CTA → 엔딩
```

리듬 장치:
- 0.4~0.8초 짧은 강조 컷
- 1.0~1.4초 설명 컷
- 2.0초 이상 유지하는 호흡 컷
- flash frame은 샷 전환/감정 피크에만 사용
- 위기 구간도 그림체를 가리면 안 된다. 색감/속도/효과는 쓰되, 원화가 보존되는 강도로만 쓴다.
- 검정 브릿지나 로고 컷으로 중간에 호흡을 끊는다

### 3. 자막이 얼굴을 가림

문제:
- 큰 한글 자막을 중앙 하단에 고정하면 얼굴, 입, 시선, 핵심 표정을 가린다.
- 이미지 크롭을 먼저 정하지 않고 자막을 얹으면 인물의 눈·입 위에 텍스트가 올라간다.

금지:
- 얼굴 중앙, 눈, 입, 중요한 손동작 위에 자막을 올리지 않는다.
- 모든 컷의 자막 y좌표를 하나로 고정하지 않는다.
- 인물 얼굴이 하단에 있는 이미지에서 하단 자막을 강제하지 않는다.

안전 영역:
- 얼굴이 상단 35%에 있으면 자막은 하단 68~82%.
- 얼굴이 중앙 35~65%에 있으면 자막은 상단 10~22% 또는 하단 78~88%.
- 얼굴이 하단 60% 이후에 있으면 자막은 상단 10~24%.
- 말풍선은 얼굴 옆 빈 공간에 두고, 꼬리만 인물 쪽으로 향하게 한다.

실무 규칙:
- 각 이미지마다 `face_safe_zone`을 잡는다.
- 자막 박스가 `face_safe_zone`과 겹치면 위치를 바꾼다.
- 자동 얼굴 인식이 없으면 최소한 주요 샘플 프레임을 직접 확인한다.

### 4. 이미지 배치가 어색함

문제:
- 캐릭터 전신 이미지가 무작정 cover crop되면 얼굴이 잘리거나, 너무 멀거나, 몸통만 보인다.
- 흰 배경 캐릭터를 그냥 전체화면에 깔면 웹툰 패널 느낌이 약하다.

원칙:
- 캐릭터 이미지는 컷마다 목적에 맞게 crop anchor를 다르게 둔다.
- 얼굴 클로즈업, 상반신, 전신, 듀오 구도를 의도적으로 구분한다.

권장 구도:
- 훅: 얼굴/상반신 클로즈업. 눈과 입이 보이게.
- 작품명/표지: 캐릭터보다 타이틀 중심. 정적이어도 됨.
- 과거/회상: 밝고 넓은 배경 + 느린 세로 팬.
- 위기: 약한 어두운 톤 + 짧은 flash + 미세 shake/zoom. 붉은 선/속도선은 최소화.
- 재회: 남녀 클로즈업 교차 또는 말풍선.
- 이벤트/CTA: 정적인 UI 화면. 여기서는 인물보다 정보 가독성 우선.

### 5. 얼굴이 프레임 밖으로 잘림

문제:
- 캐릭터를 화면에 꽉 채우려다 상단 crop이 과해지면 머리카락, 이마, 눈, 턱선이 잘린다.
- 웹툰/애니메이션형 영상에서는 얼굴 표정이 서사의 핵심이라, 의도 없는 얼굴 잘림은 바로 품질 저하로 보인다.

금지:
- `cover`만 믿고 세로 인물 이미지를 1.2~1.5배 이상 무작정 확대하지 않는다.
- 얼굴 위치를 확인하지 않고 `dy`를 음수로 줘서 이미지를 위로 끌어올리지 않는다.
- 자막 안전 영역만 확인하고 얼굴 프레임 안전 영역을 생략하지 않는다.

하드 룰:
- 의도한 극단 클로즈업이 아니라면 얼굴 전체가 보여야 한다.
- 최소한 눈, 코, 입, 턱선은 프레임 안에 있어야 한다.
- 머리카락 일부는 잘릴 수 있지만, 이마/눈썹/눈이 잘리면 실패다.
- 말풍선이나 자막보다 얼굴 보존을 우선한다.

구현 기준:
```text
bad:  scale to cover → center crop → dy negative → face/top clipped
okay: scale to cover → detect/manual face box → clamp top crop/headroom → place caption outside face box
```

실무 규칙:
- 인물 이미지마다 `face_box` 또는 최소 `headroom_px`를 설정한다.
- 자동 얼굴 인식이 없으면 keyframe sheet에서 직접 확인한다.
- 세로 인물 이미지는 기본적으로 `head-safe cover`를 쓴다.
- `head-safe cover`는 상단 crop을 제한한다. 예: top crop <= 40~80px.
- close-up이 필요하면 crop으로 얼굴을 자르지 말고, 원본에서 얼굴이 충분히 보이는 이미지를 선택한다.


### 6. 썸네일형 이미지 오버레이가 올라감

문제:
- 리듬감을 올리려고 작은 이미지 박스나 캐릭터 누끼 패널을 화면 위에 얹으면, 웹툰 컷이 아니라 편집 타임라인 썸네일처럼 보인다.
- 샷마다 비슷한 위치에 작은 패널이 하나씩 뜨면 cheap template 느낌이 강해진다.

금지:
- 명확한 앱 UI/채팅 UI 연출이 아니라면 작은 이미지 썸네일을 floating overlay로 올리지 않는다.
- 얼굴이나 배경 위에 border/shadow가 있는 작은 인물 박스를 반복 배치하지 않는다.
- 리듬 보강 목적으로 임의의 inset/cutout thumbnail을 붙이지 않는다.

원칙:
- 리듬은 `full-frame 샷 변화`, `카메라 속도 변화`, `짧은 beat flash`, `검정 브릿지`, `말풍선 pop`, `전경/날씨/조명 변화`로 만든다.
- 여러 컷을 한 화면에 넣어야 한다면 floating thumbnail이 아니라 웹툰 페이지처럼 의도된 큰 패널 분할을 쓴다. 예: 좌우 50:50, 상하 60:40, full-height vertical split.
- 작은 보조 패널은 실제 UI 화면, 지도, 편지, 메시지 캡처처럼 서사적 물건일 때만 쓴다.

구현 기준:
```text
bad:  base panel 위에 300x500 캐릭터 썸네일을 매 샷마다 띄움
okay: base panel 유지 + cue 시작 0.09s gold flash + 말풍선 pop
okay: 다음 장면을 full-frame으로 hard cut / swipe / black bridge
okay: 웹툰 페이지처럼 화면 절반 이상을 차지하는 명확한 panel split
```

### 7. 검은 막대·사각형·접지 타원이 보임

문제:
- 창살/울타리/전경 실루엣을 대충 사각형으로 그리면 장식이 아니라 검은 막대처럼 보인다.
- 누끼 캐릭터에 tint를 전체 사각형 레이어로 합성하면 투명 영역까지 색이 깔려 박스가 생긴다.
- waist-up 캐릭터 밑에 contact shadow 타원을 그리면 인물이 바닥에 서 있는 게 아니라 검은 구멍 위에 떠 있는 것처럼 보인다.
- 좌우 vignette를 선형으로 시작시키면 화면 오른쪽/왼쪽에 세로 사각형 띠가 생긴다.

금지:
- 의도와 맥락이 명확하지 않은 검은 창살/울타리/막대 전경.
- 캐릭터 alpha mask 없이 전체 bbox에 tint, shadow, glow를 입히는 방식.
- 발이 보이지 않는 반신/상반신 누끼에 바닥 접지 타원을 넣는 방식.
- 프레임 안쪽에서 갑자기 시작되는 좌우 vignette/edge shade.

원칙:
- 전경 요소는 “무엇인지” 읽혀야 한다. 못 읽히면 삭제한다.
- tint/shadow/glow는 캐릭터 alpha에만 묶는다.
- 반신 누끼는 바닥 접지보다 `bottom feather/clear + soft alpha-bound separation shadow`가 자연스럽다.
- 검은 막대처럼 보이는 이펙트는 레퍼런스에 있어도 로컬 자산과 안 맞으면 버린다.

구현 기준:
```text
bad:  d.rectangle((x, 920, x+44, 1620), fill=black_alpha)
bad:  alpha_composite(full_bbox_tint)
bad:  waist-up cutout 아래 black oval shadow
okay: character_alpha_masked_tint
okay: cutout bottom feather/clear
okay: alpha-bound blurred separation shadow
okay: foreground는 커튼/안개/눈/낙엽처럼 이미지와 섞이는 요소만 사용
```

### 8. 원본 이미지 워터마크·글자·하드 crop edge가 보임

문제:
- 캐릭터 소스에 작은 글자/워터마크성 텍스트가 남아 있으면 광고 영상 품질이 바로 떨어진다.
- 원본 이미지가 이미 팔/소매/머리카락을 화면 가장자리에서 잘라 둔 경우, 누끼 후 중앙에 배치하면 세로 mask edge처럼 보인다.

원칙:
- cutout sheet는 흰 배경이 아니라 어두운 checker/background에서도 확인한다.
- 캐릭터 내부의 글자·워터마크·불필요한 원본 텍스트는 retouch하거나, 해당 부위가 화면 밖/다른 캐릭터 뒤로 가도록 배치한다.
- source-side crop edge가 보이면 캐릭터를 프레임 가장자리 쪽으로 밀거나, 더 적합한 이미지를 고른다.

검증:
- 훅/대표 컷은 full-res keyframe으로 본다. contact sheet 축소본만 보면 작은 글자와 crop edge를 놓친다.
- 누끼 자산은 `white`, `dark`, `checker` 배경에서 각각 확인한다.

## 자막 가이드

### 스타일

- 웹툰 추천형은 굵은 한글 자막이 맞다.
- 기본 색상: 노랑, 초록, 흰색.
- 위기 키워드는 빨강.
- stroke는 충분히 두껍게 둔다.

권장:
```text
노랑: 장르/핵심 키워드
초록: 작품명/효능/긍정 포인트
흰색: 설명 연결어
빨강: 위기/죽음/저주/정체 등 피크 단어
```

### 위치

- 자막 위치는 컷마다 다르게 잡는다.
- 같은 컷 안에서도 말풍선/상단 자막/하단 자막을 섞는다.
- 얼굴이 중앙이면 하단 자막을 줄이고 상단 박스나 사이드 말풍선을 쓴다.

### 길이

- 한 화면 자막은 1~2줄.
- 줄당 12~18자 정도가 가장 안전하다.
- 3줄 이상은 피한다.
- 긴 설명은 자막 큐를 나누되, 카메라 모션은 이어간다.

## 모션 가이드

### 카메라

- 자막 변경마다 카메라가 리셋되면 안 된다.
- 같은 visual scene에서는 하나의 모션 곡선을 유지한다.
- `zoom in`, `slow pan`, `push`, `hold`, `shake`를 샷 기능에 맞춰 다르게 쓴다.

예시:
```text
0.0–2.7s 훅: slow zoom in
2.7–5.7s 효능: bright flash + soft push
5.7–8.5s 표지: static hold + subtle scale
8.5–11.5s 브릿지: static black card
14.5–18.8s 회상: slow vertical pan
18.8–24.7s 위기: quick cuts + subtle flash/vignette + micro shake
24.7–29.8s 재회: alternating closeups + speech bubble
36.8–43.8s 이벤트: static UI
43.8–49.2s 엔딩: logo hold
```

### 이펙트

원칙:
- 이펙트는 이미지를 돋보이게 해야 한다. 원화/그림체를 가리면 실패다.
- 강한 빨간선, 과한 speed line, 진한 tint, 두꺼운 대각선 slash는 지양한다.
- 위기감은 색을 덮는 방식보다 `짧은 컷`, `미세 shake`, `subtle zoom`, `짧은 flash`, `약한 vignette`로 만든다.

금지:
- 얼굴·상체 위를 지나가는 굵은 빨간 대각선.
- 화면 전체를 덮어 그림체 채도/명암을 죽이는 붉은 오버레이.
- 1초 이상 지속되는 강한 speed line.
- 자막/이펙트/말풍선이 동시에 겹쳐 원화가 안 보이는 상태.

권장 강도:
```text
vignette alpha: 60~120
color tint alpha: 12~35
crisis tint alpha: 최대 35~45
flash: 0.08~0.18, 0.1초 이하
speed line: 배경/가장자리 위주, alpha 20~50
```

위기 구간 대체법:
- 빨간선을 긋기보다 배경을 살짝 어둡게 한다.
- 캐릭터 얼굴은 건드리지 않고 가장자리 vignette만 준다.
- 한 컷을 0.7~1.0초로 짧게 가져가 리듬으로 긴장감을 만든다.
- 붉은 키워드는 자막 색에서만 쓰고, 이미지 위 효과는 약하게 둔다.

### 컷 밀도

- 웹툰 설명형: 대략 0.75~1.0 visual changes/sec.
- 비트싱크형: 1.5~4.0 visual changes/sec까지 가능.
- 설명형 영상에서 너무 빠르면 내용이 안 읽히고, 너무 느리면 쇼츠 리듬이 죽는다.

주의:
- visual changes/sec만 맞추지 말고, 기능 변화가 있어야 한다.
- 같은 이미지 반복을 컷 수로 계산하지 않는다.

## 레이아웃 검증 체크리스트

렌더 후 반드시 확인한다.

### 프레임시트

- `fps=2` 정도로 전체 프레임시트를 만든다.
- 주요 장면은 별도 keyframe sheet를 만든다.
- 같은 이미지가 원점으로 튀는지 확인한다.
- 4~6초마다 화면 기능이 바뀌는지 확인한다.

### 얼굴/자막 겹침

샘플 프레임마다 확인:
- 얼굴이 자막에 가려졌는가?
- 눈/입/핵심 표정이 가려졌는가?
- 인물의 시선 방향에 자막이 방해되는가?
- 말풍선 꼬리가 얼굴을 침범하는가?

### 리듬감

확인할 것:
- 초반 3초 안에 후킹이 있는가?
- 10초 안에 브릿지/작품명/전환이 있는가?
- 중반 위기 구간에서 컷 속도와 색감이 바뀌는가?
- 후반 CTA나 이벤트 구간이 너무 빨리 나오지 않는가?
- 엔딩이 검정/로고/CTA로 명확히 닫히는가?

### 얼굴 프레임 보존

샘플 프레임마다 확인:
- 머리, 눈, 입, 턱선이 프레임 밖으로 잘렸는가?
- 인물이 너무 상단에 붙어 답답해 보이는가?
- 카메라 줌이 진행되면서 후반부에 얼굴이 잘리는가?
- 말풍선/자막을 피하려다 얼굴을 위로 밀어 올리지는 않았는가?
- 의도한 극단 클로즈업이라면 그 의도가 storyboard에 명시되어 있는가?

## 산출물 요구사항

비슷한 작업을 수행할 때는 최소한 아래를 남긴다.

- 최종 MP4
- preview strip 또는 contact sheet
- keyframe check sheet
- storyboard JSON 또는 markdown
- 사용한 생성 스크립트
- ffprobe 결과
- 리듬/레이아웃 검증 요약

## 현재 작업에서 나온 추가 피드백

- “리듬감이 더 있어야 한다.”
  - 컷 수만 늘리지 말고, 감정 피크와 visual mode 변화를 늘린다.
- “이미지 배치 위치가 이상하다.”
  - 각 이미지별 crop anchor를 수동으로 잡는다.
- “글자가 얼굴을 가린다.”
  - 자막 안전 영역을 컷마다 다르게 적용한다.
- “캐릭터 얼굴이 너무 상단에 배치되어 잘린다.”
  - 웹툰형 영상에서 의도 없는 얼굴 잘림은 실패다. head-safe cover와 face frame 검증을 적용한다.
- “빨간선/과한 이펙트가 그림체를 가린다.”
  - 강한 red slash/speed line/tint는 지양한다. 이미지를 잘 살리는 subtle effect 중심으로 만든다.
  - 긴장감은 빨간선을 덮는 방식보다 컷 길이, 약한 vignette, 미세 shake, 자막 키워드 색으로 만든다.
- “같은 이미지가 원점으로 반복된다.”
  - caption cue와 visual scene을 분리하고, 카메라 motion progress를 visual scene 기준으로 계산한다.

- “샷마다 비슷하다.”
  - 작은 썸네일 오버레이를 붙이지 않는다. full-frame 전환, cue flash, 말풍선, 브릿지, 조명/전경 변화로 리듬을 만든다.
- “생성 모델이 투명 배경을 지원하지 않는다.”
  - opaque 생성 후 edge-connected light background 제거로 누끼를 만들고, cutout sheet에서 배경 잔여물을 확인한다.
- “12초쯤 캐릭터 뒤 검은 막대/사각형이 보인다.”
  - 못 읽히는 창살/울타리 실루엣은 삭제한다. tint/shadow는 bbox가 아니라 캐릭터 alpha에만 적용한다.
- “소스 자체가 어설프게 보이는 부분이 있다.”
  - 작은 원본 글자/워터마크성 텍스트, source-side crop edge, hard bottom edge를 full-res keyframe으로 확인하고 retouch/배치 보정한다.

## 반복 제작 우선순위

1. 레퍼런스 스토리라인/샷 기능을 먼저 분해한다.
2. 각 샷마다 `background plate`, `character cutout`, `foreground overlay`, `visual purpose`, `image anchor`, `face frame safe zone`, `caption safe zone`, `motion curve`, `cutout cleanup`을 정한다.
3. 필요한 배경은 먼저 생성하고, 핵심 캐릭터만 누끼로 분리한다.
4. 렌더 후 프레임시트로 얼굴 잘림, 자막-얼굴 겹침, 모션 리셋을 확인한다.
5. 리듬감이 약하면 컷을 무작정 늘리지 말고, 위기/브릿지/말풍선/이벤트/엔딩처럼 화면 기능을 추가한다.
6. 위기 이펙트는 원화를 가리지 않는지 먼저 확인한다. 빨간선이 그림체보다 먼저 보이면 실패로 보고 낮춘다.
